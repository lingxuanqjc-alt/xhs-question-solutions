# 竖屏发布视频脚本

建议成片：75–90 秒，1080 × 1920，屏幕录制 + 大字幕 + 真人或自然口播。所有评论均使用 `examples/` 中的虚构数据；成片说明区标注 AI 辅助。

## 主版本

| 时间 | 画面 | 旁白 | 屏幕字幕 |
|---|---|---|---|
| 0–4 秒 | “喷酒精就行”与“有火灾风险”两条评论快速对撞 | 同一个问题，评论区给了完全相反的答案，你会信哪条？ | 高赞 ≠ 正确 |
| 4–10 秒 | 再闪过“亲测两年没复发”“一周后又长了” | 真正有用的不是把评论总结一遍，而是分清答案、亲历、反例和风险。 | 答案 / 亲历 / 反例 / 风险 |
| 10–18 秒 | Codex 中输入 `$xhs-question-solutions` | 所以我做了一个同时支持 Codex 和 Claude Code 的开源 Skill。 | xhs-question-solutions |
| 18–29 秒 | 两篇候选笔记，一篇被保留、一篇教程钩子被排除 | 它先判断谁真的在提问，不会看到问号就算问题帖。 | 先筛真问题 |
| 29–43 秒 | 评论依次贴上类别、证据质量和风险标签 | 每条取得的评论都要分类；软广、复制话术和让 Agent 忽略规则的内容会被单独标记。 | 评论是“不可信数据” |
| 43–57 秒 | 展示 3 个步骤，各自出现 claim 与 c1/c3/c4 | 然后先建主张账本，再生成方案。每一步都要写适用条件、验证信号、停止条件和原评论 ID。 | 每一步都能回到证据 |
| 57–67 秒 | 突出“页面显示 12 条、实际采集 9 条”与冲突卡 | 如果评论没取全，它会直接显示覆盖率；遇到冲突，也不会替你悄悄平均。 | 实际采集 9 条 · 样本截断 |
| 67–77 秒 | 报告、10 张主卡及 3 张证据附录、短视频分镜切换 | 同一份已校验分析，可以输出完整报告、可直接预览的图文卡片和短视频分镜。每个动作独占一张，文字溢出会停止而不是裁掉。 | 一个事实源 · 三种呈现 |
| 77–85 秒 | GitHub 首页、测试状态和 Release 页 | 项目已开源，Windows、macOS、Linux 都能安装。 | github.com/lingxuanqjc-alt/xhs-question-solutions |
| 85–90 秒 | 定格项目名与证据索引 | 想把评论区经验变成可追溯方案，可以从示例开始试。 | 开源 · 可验证 · 不伪造共识 |

## 封面与标题 A/B

- A：`评论区答案互相打架？这个 Skill 先帮你分清证据`
- B：`我把小红书评论整理成了“每一步都有出处”的方案`

封面只选一个承诺：`高赞不等于有效答案`。不要同时堆叠功能清单。

## 发布文案

```text
小红书的问题帖里，经常同时出现直接建议、亲历经验、失败反例、风险提醒和随口猜测。

我做了 xhs-question-solutions：先筛出真正的问题帖，再把取得的每条评论分类，建立主张账本，最后生成每一步都能回到评论 ID 的方案。样本截断、观点冲突和高风险内容也会明确显示。

支持 Codex 与 Claude Code，项目和完全虚构的演示数据已经开源：
github.com/lingxuanqjc-alt/xhs-question-solutions

本视频与示例由 AI 辅助制作；不包含真实用户数据。使用时请遵守平台规则，只处理公开内容或你有权访问的数据。
```

## 录制与验收清单

- 使用 `examples/sample-input.json`，不得展示真实 Cookie、账号、通知、本地绝对路径或用户导出。
- 录制一次真实的 Skill 调用，而不是只翻页展示预制结果。
- 同屏展示评论 ID 与对应步骤；至少展示一次截断提示、一个反例和一个冲突。
- 展示 `examples/sample-cards/` 中真实渲染的封面、动作卡、风险卡与末卡；不得把 Markdown 文案截图冒充图文成品。
- 口播和字幕保留“评论个案”“样本截断”“待权威复核”等限制词。
- 导出前检查 GitHub 链接、字幕安全区、声音响度、AI 辅助披露和无敏感信息。
- 发布后分别观察有效观看、收藏、分享、有效追问和后续验证反馈；不要用点赞判断内容真实性。
